# 시제품 v0.2 전체 테스트

목표: 가사 입력에서 읽기 교정, 번역, 재변환, 파일 복원과 위키 출력까지 직접 확인합니다. 예제는 테스트용 짧은 문장입니다.

## 시작

Python/Node 의존성을 README대로 설치한 뒤 Windows에서는 `./scripts/start.ps1`, macOS/Linux에서는 `sh scripts/start.sh`를 실행합니다. <http://127.0.0.1:8000>을 엽니다.

앱의 **프로젝트 불러오기**에서 `fixtures/demo-project.json`을 선택합니다.

위키 표는 일반 텍스트만 입력하는 것을 전제로 이스케이프합니다. 루비나 기존 위키 문법을 붙여 넣으면 문법 자체가 문자로 출력됩니다. 실제 위키의 테마·파서 미리보기는 게시 전에 별도로 확인합니다. 이 앱은 위키에 자동 게시하지 않습니다.

## 자동 검사

Windows: `./scripts/test.ps1`. Playwright 브라우저는 최초 한 번 `cd frontend; npx playwright install chromium`으로 설치합니다.

검사는 다음을 포함합니다.

- 표기 규칙·입력 한계·원문 구간 보존·사전 우선순위·범위 중첩 오류
- 구간 병합·재변환·번역 보존·위키 이스케이프·프로젝트 스키마 검증
- 실제 브라우저에서 사전→교정→번역→복사→다운로드→가져오기 전체 흐름
- 연결 실패 후 재시도, 손상된 초안 복구, 모바일 레이아웃
- GitHub Actions의 Linux 실행 및 Docker 빌드·화면/API 기동 검사

실제 빌드 결과로 브라우저 검사를 실행하려면 통합 서버를 켠 뒤 `PLAYWRIGHT_BASE_URL=http://127.0.0.1:8000` 환경변수로 `npm run test:e2e`를 실행합니다. CI도 이 경로를 사용합니다.

## 알려진 범위

- 자동 읽기는 실제 노래와 다를 수 있습니다. 표시가 없는 한자도 검수해야 합니다.
- 곡 사전은 정확히 일치하는 문자열을 대상으로 하며 문맥별 적용은 하지 않습니다. 특정 위치의 수정으로 예외를 만듭니다.
- 원문·행 위치가 바뀌면 그 위치의 교정·번역을 자동 이동하지 않습니다. 변경된 행은 다시 확인합니다.
- 음원 분석, AI 후보, 자동 번역, URL 가져오기, 계정 동기화는 포함하지 않습니다.
- 서버는 로컬 주소에만 연결합니다. 외부 공개 주소가 필요한 배포는 별도 운영 환경에서 진행합니다.
